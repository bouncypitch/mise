A voice request is decomposed into an ingredient list, a robot retrieves each raw ingredient, kits them into a tray, then cuts and preps them so they're ready to cook.

Kitting is a repeatable task across industries — meal kits, hospitals, warehouses. We built that one piece, well.

The Problem

Agents fail silently

"An agent that succeeds 99% of the time still fails a 100-step task more often than not."

Architecture

How it thinks

GOAL
→
PLAN
→
ACT
→
OBSERVE
→
VERIFY

on fail

DIAGNOSE
→
REPLAN
→
ACT AGAIN

Hard boundary: the LLM only interprets goals, diagnoses failures, and replans — named parameters, never joint angles. IK, motion, grasp, and verification are deterministic Python, the same code path every run.

The LLM never touches a trajectory. Physics is run by code, not a model.

Mid-Run Verification

How does it recognize failure

GRIPPER CHECK
→
LIFT CHECK
→
VERIFIED

dist(gripper, object) < 0.06m  AND  object height > table + 0.05m

verifier.py is deterministic, zero LLM involvement. It independently re-derives success from observed physics — never from what the controller claims happened.

Every result is checked against the world model — the checkpointed record of what should be true for each object. A mismatch is logged as expected vs. observed and written to disk immediately.

The seeded failure closes the gripper on empty air — caught from geometry alone.

Failure Recovery

How does it recover

DIAGNOSE DRIFT
→
PICK NEW STRATEGY
→
REPLAN
→
ACT AGAIN

Example: a missed grasp on basil is classified as behavioral drift — right object, right timing, wrong execution. The planner swaps in a genuinely different strategy — a lower, rotated side-grasp — not a blind retry of the same motion.

Recovery is a different strategy, not the same action repeated.
